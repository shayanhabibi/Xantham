### 2. Root cause
Verified by reading the code and by the repro:
- `src/Xantham.Generator/Shape/Spec.fs:637` `exclusiveArmShape` is the single decision point. `names` (:650) and `classify` (:663) iterate `arm.Members` only. `TypeFacts.IndexInfos`, `CallSignatures` and `ConstructSignatures` (`Model.fs:1277-1281`) are never inspected, so signatures neither block the fold nor take part in the "every arm agrees" check. `isObjectArm` (:643) tests only `Members.IsEmpty`.
- `ExclusiveArm` (Spec.fs:608) and `ExclusiveArmsFold(shared, arms)` (:623) carry `ResolvedMember` lists only, so the signatures cannot reach the builder.
- `src/Xantham.Generator/Shape/Interfaces.fs:406-462` `foldedDecls` builds the folded FsInterface with `Members = sharedMembers @ exclusiveMembers` (:453).
- The arms are in `foldedArmIds` (Interfaces.fs:86), so the ordinary per-arm path that emits FsInvoke, FsIndexer and FsConstructor and raises SI008, MB004 and SI004 (:283-346) never runs for them. The signatures and their findings disappear with no trace.

Inference: `Anonymous.fs:718` and `Orphans.fs:158` call the same predicate, so a predicate-level fix keeps naming, orphan pruning and the declaration consistent.

### 4. Fix options
1. **Decline whenever any arm carries signatures.** In `exclusiveArmShape`, return `NotExclusiveArms` when any arm has a non-empty CallSignatures, ConstructSignatures or IndexInfos. This changes `Spec.fs` only, plus the doc comment on `ExclusiveArmsShape`. Findings: none new. The U2 arms raise their own SI008, MB004 and SI004. Churn: `tagged-arm-lab` T1 and T2 become `U2<..>` with minted arm interfaces, and TR060 drops by 2 there. Nothing else changes. Risk: low. CallBoth and IndexBoth lose the fold's Create overloads, which is an ergonomic regression only.
2. **(Recommended) Classify signatures the way members are classified.** Hoist signatures that are identical on every arm and decline otherwise.
   - Spec.fs: when every arm carries pairwise-matching call signatures, carry them as `sharedCalls` on `ExclusiveArmsFold`. Matching means the same count and, for each signature, the same parameter `sameShape`, Optional, HasRest and return. Keep it conservative by requiring no own type parameters.
   - Spec.fs: likewise carry matching IndexInfos as `sharedIndexes`. Matching means equal KeyTypeId, `sameShape` ValueTypeId and equal IsReadonly.
   - Spec.fs: anything else, and any construct signature at all, returns `NotExclusiveArms`.
   - Interfaces.fs `foldedDecls`: render the shared signatures with the ordinary path's builders. Call signatures go through `shapeSignature` to `FsInvoke` (Interfaces.fs:313-331), including the `invokeCollides` and SI007/SI008 handling. Index signatures go through the indexer builder near Spec.fs:3922 to `FsIndexer`, with MB004.
   - `ParamObjects.fs:146` already skips decls that have CreateOverloads, so SP003's index refusal does not trigger.
   - Findings: none new.
   - Churn: the same as option 1 in tagged-arm-lab (both of its cases are one-arm), plus the lab additions. No real-fixture churn.
   - Risk: medium, mostly in signature equality. A wrong equality falls back to a decline, which is safe.
3. Keep the fold and add an Escape finding for the dropped signatures. This is honest but lossy where a lossless shape exists, so it is not recommended.

Recommend option 2. Option 1 is exactly its decline half and can land first.
